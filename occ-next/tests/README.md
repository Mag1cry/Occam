# tests/ — 测的是「**用户能感受到的东西**」

两条判据，别的都只是手段：

1. **按下去真的生效了吗** —— 屏幕上那个按钮，用户期望发生的那件事**真的发生了**吗
2. **该显示的显示全了吗** —— 用户要看的那几样，是不是都在，是不是缺了一大块

**为什么用这个轴**：模块测试、契约测试、边界测试可以全绿，而用户点下去什么都没发生。
因此 UI 命令测试之外仍需要真后端联调；下面的表记录的是实现与覆盖状态，不应解读为每项都已做过浏览器实测。

**哪些是"感受到"**：按下按钮之后系统里的变化（能用重读证明）、屏幕上出现/消失的东西、
报错时用户读到的那句话。**哪些不是**：函数名、模块边界、内部字段——那些是手段，红了再修。

| 跑什么 | 命令 |
| --- | --- |
| 后端 | `uv run pytest -q` |
| 前端（在 `../../occ-command-center`） | `npm test` |
| **联调**（需要真后端，默认跳过） | 见 `../../occ-command-center/src/api/live.test.ts` 头部 |
| **起一套来点** | 后端 `OCC_NEXT_ROOT=demo uv run occ-next`；前端 `npm run dev` |

夹具在 [`support/`](support/)：`newtree.py` 是**最小可跑的一整个系统**（两个包 + 一条日程 +
一家供应商，worker 是真子进程），`newcore.py` 是内核的快捷动作，`mcpserver.py` 是说真协议的假 MCP 服务器。

## 一、按钮：按下去到底会发生什么

**联调口径**：命令发到隔离的真后端（`demo` 那棵树），看它收不收、完成后系统状态是否变化。

> 联调覆盖用例见 `../../occ-command-center/src/api/live.test.ts`；"谁钉住它"列给出对应自动化覆盖，
> 不代表这些流程已在当前环境逐条手动实测。

### 按钮怎么测

| 层 | 测什么 | 测不出什么 |
| --- | --- | --- |
| 前端单测（桩 fetch） | 按钮**提交了哪条命令、带了哪些栏** | **后端收不收**——桩不会说不 |
| **联调**（真后端） | 按下去 → **重读状态** → 系统里真的变了 | — |
| 一边按一边看 | 报错时**用户读到的那句话**说清了吗 | — |

> B2/B3 值得单独说一句修法：那句原因（谁批的）**该由接入面填，不该由前端送**——
> 前端自称"我批的"不是证据。`web/http.py` 里从已认证的调用方取，四行。

## 二、内容：该显示的显示全了吗

**快照检查口径**：拿真后端的快照跑一遍投影，看该出现的节点/字段**在不在**。
空列表最容易骗人——它看起来像"还没有数据"，而不是"接错了"。

| # | 界面 | 用户要看 | 现在 | 缺什么 |
| --- | --- | --- | --- | --- |
| C1 | 世界场景 | 有哪些任务、各自什么状态、谁在跑 | 任务 + 状态 + 审批 + `controllers`（谁在跑） + 事实流 | 运行中状态由后端快照给出 |
| C2 | 任务详情 | 它要干什么、干到哪了、**结果是什么** | 任务字段 + 最近事件；结果通过 `GET /api/tasks/{id}` 按需读取 | adapter 可用性由执行者决定；读取失败或不支持时前端须显示原因 |
| C3 | 智能体审计面板 | 模型这一路说了什么 | `GET /api/tasks/{id}/agent-audit` 按需读取 adapter；LangGraph 托管执行者提供消息与工具调用投影 | 其他执行者未必提供审计；外部 Agent 监控契约另行设计 |
| C4 | 配置舱 | 扩展、工具供给、执行者、日程、供应商与诊断 | 按后端注册表呈现声明和启停状态 | 供应商模型目录在执行者配置选项中提供 |
| C5 | 配置舱 | 设备、MCP | 设备不作为独立对象；MCP 以工具供给接入 | 外部 Agent 监控尚无注册表或界面契约 |
| C6 | 日程场景 | 有哪些日程、跑过没有 | 日程 + 派发记录 | 不在当前快照契约中的派生信息不展示 |
| C7 | 全局 | 出错时那句人话 | 后端校验错误返回原因；服务端错误保留 500 | 接口错误需结合日志定位 |

### 内容怎么测

**内容测试**和按钮测试是同一个动作的两面：**拿真快照断言"该有的都在"**。
写成一条：`配置舱的节点数 > 0`、`每个包都有一个节点`、`关着的供给仍出现在列表里且标着已下线`。
——这类断言很笨，而它们抓的正是"接错了字段 → 界面上少一整块"。

## 四、写的时候的规矩

1. **用例名说人话**：`test_批准了甲不能执行乙` 比 `test_fingerprint_mismatch` 有用——
   半年后红的是哪一个、它本来保证什么，名字里就写着。
2. **一条只钉一件事**，且不依赖别的用例留下的状态（`newtree.application(tmp_path)` 每回都是干净的一份）。
3. **断言落在用户能感受到的东西上**（状态、答复、屏幕上的节点），不落在内部函数名上。
4. **联调那一层不能省**：桩测试证明"前端送了"，只有真后端能证明"真的生效"。

**仍待实现或定义的运行能力**：网关侧工具调用结果与耗时持久化、工具调用超时与重试语义、
事件链保留与归档、外部 Agent 监控契约、完整成本遥测及分析 Agent。加入具体用例前，先明确
对应的用户可观察行为和事实来源。
