# web/ — 网页接入

HTTP、只读投影、事实流。前端只有这几个口。

| 文件 | 装什么 |
| --- | --- |
| `http.py` | HTTP 路由 |
| `snapshot.py` | 只读投影：**前端唯一的事实入口** |
| `references.py` | 三态引用解析：可解析 / 已下线 / 未知 |
| `streaming.py` | SSE 事实流：只标记「谁脏了」 |

## 边界

- **不拥有业务流程**。每个路由只做三件事：解析请求 → 翻译成网关命令 → 映射错误码。
- **不判权限**。谁能进来是 `gateway/access/` 的事——这里只把它的结果挂成 FastAPI 依赖，
  并把 401 和 `WWW-Authenticate` 头翻译出去（浏览器不看到那个头就不会弹登录框）。
- **不推派生结果**。事实流只说哪些对象脏了，状态一律来自重读（ADR-031）——
  两侧各算一遍就是漂移的来源。
- **不碰存储**。内核的存储由 `core/kernel.py` 绑定。

## 配置舱：同一个事实的另一种组织

前端的主视图叫**配置舱**。它和注册表**看的是同一份事实**，只是组织方式不同：

| 视图 | 按什么组织 | 谁读 |
| --- | --- | --- |
| **注册表**（那四个列表） | 按**类型** | 后端判决、起 worker、派发 |
| **配置舱** | 按**声明文件**（包 / 独立文件） | 人 |

```text
weather                 [包]
├─ collect              [工具] [执行者]     ← 名字相同 → 同一个节点两个词条
├─ alert                [工具]
└─ current              [工具]

deepseek                [供应商]
├─ deepseek-flash
└─ deepseek-v4-pro

weather.daily           [日程]
```

**它是投影，不是第五份数据。** 两份数据一定会漂移，而"这条来自哪份声明"扫描期本来就有，
只是拍平进列表时丢掉了——加回来只要一个字段。

**同一份声明里的两条按名字缝成一个节点**：工具的 `供给名.函数名` 和执行者的全名对上，
人就看到一个函数带两个词条。（见 `extensions/README.md`。）

## 投影里必须有"关着的那些"

四个列表是**前端渲染的唯一依据**（`gateway/directory/README.md`）。投影要是把 `enabled: false`
的东西滤掉，前端就只能自己另编一套"关着的扩展"的概念——于是同一件事又变成两处在说，
而它们会漂移。

所以投影**照单全收**，关着的那些答"已下线"（三态见 `references.py`）。前端照常渲染，
只是点不动。

## 为什么 snapshot / references 在这里而不在 gateway

它们是对外契约：`snapshot.py` 是前端唯一的事实入口（ADR-032），`references.py` 回答
"这条历史引用还能读回来吗"。它们经由网关暴露，但承担的是接入面的责任。

## 别踩回去的坑

权限检查必须挂成 **router 级依赖**，不是中间件：依赖跑在路由之后，所以不存在的路径仍然是 404。
中间件会把它变成 401，那既改变了对"这个接口不存在"的答复，也让故意不存在的路由看起来像认证问题。
