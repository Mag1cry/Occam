# core/ — 内核

四个原语 + 控制事件。**不运行、不做 IO、不判决**：不认识进程、网络、文件、扩展、数据库。

| 文件 | 装什么 |
| --- | --- |
| `kernel.py` | 绑定：接上存储，露出命令（**只转发，不许有 if**） |
| `task.py` | Task 原语 + `TaskStore` + 四条命令 + **全部迁移** + 它的事件 |
| `capability.py` | Capability 原语：所有函数调用的审计记录 + 五条命令 + 审批与兑现的三条规则 |
| `event.py` | Event Chain 原语 + `EventStore` + `new_event` 模具（**不产生事件**） |
| `executor.py` | Executor 原语——**只剩一根引用**（`SetSubjectState` 已删，理由见文件里） |
| `store.py` | 共用：事务 / 命令的形状 / 迁移通道 |
| `errors.py` | 共用：稳定的内核错误 |

## 边界

- 不 import 任何具体实现。`tests/unit/core/test_pure_core_ports.py` 守着这条。
- **改状态只能走迁移通道**（`store.py` 的 `commit()`）：它要求同时给出要记的事件，
  写不出"改了忘了记"的那种代码（ADR-019 的落点）。
- **不判要不要审批，也不知道有哪些工具**。判决在网关（见 `gateway/README.md`）；
  内核收到的是"这次调用，判定是 X"，不是"请你判一下"。
- **不校验"这个执行者引用存在吗"**。那是网关提交命令前的检查。
- Task 是纯数据；迁移是这个文件里的**函数**——不让它长出方法。

## 存储只出现在两个地方

**装配**（决定用哪个）和**内核**（用它）。中间任何一层都看不见——

```python
kernel = Kernel(store)        # app/build.py 决定一次，来自配置
kernel.create_task(command)   # 外围只调命令，不碰存储
```

`Kernel` 是个**把手，不是个大脑**：持有 store，一行转发到原语的命令函数。
不许有 `if`、不许构造事件、不许读 Task、不许校验——出现任何一样，
就说明规则长进绑定里了，那就是 `CoreControlPlane` 回魂（它被拆掉正是因为它全装在了一起）。

## 每个原语文件是自洽的

打开 `task.py`，你就看到 Task 是什么、它需要被怎么读写、有哪几条命令作用于它、
它们怎么迁移、产生哪几条事件。不用去别处拼。

**"共用"只有两个文件**，判据是同一条：**不属于任何一个原语，但每个原语都要用**。

| 文件 | 装什么 | 为什么不属于某个原语 |
| --- | --- | --- |
| `store.py` | 事务 / 命令的形状 / 迁移通道 | 事务跨四个原语；命令不是第五原语（ADR-036）；通道只有一条 |
| `errors.py` | 稳定的内核错误 | 四个原语抛同一批错 |

除此之外没有第三个。加东西进来之前先回答"它属于哪个原语"——**答不上来的才有资格**。

## 内核只存两样东西

| 原语 | 存哪 |
| --- | --- |
| Task | `tasks` 表（`TaskStore`） |
| Event Chain | `control_events` 表（`EventStore`） |
| **Capability** | **寄在 Task 的字段和事件链上**——没有自己的表 |
| **Executor** | **没有存储，也没有命令**——只有一根引用 |

待审批的那几格长在 Task 上（"这件事卡在等人批"本来就是委托的状态），审计记录长在事件链上。
这不是省事，是如实的。

## 四个原语

要办什么（`task.py`）· 谁负责推（`executor.py`）· 允许做什么、谁批的（`capability.py`）·
确认了什么（`event.py`）

注意第三个：内核保留的是**结果与审计**（准了、谁批的、做过没有），不是**判决**。
