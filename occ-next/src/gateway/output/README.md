# gateway/output/ — 把一件事送到外面去，以及它怎么回来

**内核只认四原语，而"外面"不止一个地方。** 今天要送出去的有三样——审批、结果、
（以后的）申请——而能送到的地方也会不止一个：**前端是内建的那一条路**（它已经在做这件事：
操作牌上两个按钮，点下去产出一条带 `web:<principal>` 证据的命令），飞书是插件的那一条，
以后可能还有别的。

这一层定的是**一份描述**和**多条路径**。它不是第五份事实。

| 文件 | 装什么 |
| --- | --- |
| `output.py` | 形状 + **从已有事实现算**：审批 ← `pending_*`；结果 ← `COMPLETED.result_ref` |
| `paths.py` | 每条路怎么把它送出去（前端 JSON / 飞书卡片 / …） |
| `callback.py` | **回来那一步**：一次点击 → 一条带证据的命令（见下） |

> 状态：**四片都落地了。** 剩下没做的只有"申请"那一种 `kind`（它没有生产者）。

## 边界

- **它不存状态。** 输出是**投影**：审批在不在、结果是什么，答案都在内核里，这里只是
  "外面那一面"，随时可以重算（`web/snapshot.py` 那条"投影不是第五份数据"，同一个道理）。
  所以这个结构里**没有** `status: sent|decided`，也**没有** `sent_at`。
  **"送过没有"是路径那一侧的账**：飞书得记住"这张卡片发过了"，否则每次扫描都重发。
- **它不是权限。** 谁能批、批了算不算，判在 `permission/` 与内核；这里只负责
  "让外面够得着"。
- **它不搬事实。** 出去的是**引用 + 摘要**，不是 Task 的字段、不是结果的正文
  （ADR-008 只留 `result_ref`，这条照它）。
- **不拥有进程、不碰存储**——和整个 `gateway/` 同一条。

## 触发点：需要审批 / 输出申请的那一刻

审批这套东西**不改**——指纹、pending 那四格、`approve`/`deny`、门面自动恢复、worker
重放兑现，全按今天的样子（`core/capability.py` + `gateway/facade.py::_recover`）。

变的只是**"停下来"这一步之后要多做一件事**：

```text
⑦ worker 决定停  channel.report(INTERRUPTED, {checkpoint_ref})
⑧ controller     kernel.interrupt(...) → running→paused，记 INTERRUPTED
   ↑ 到这儿为止和今天一模一样
   └→ 由这两个事实（FUNCTION_APPROVAL_REQUESTED / INTERRUPTED）驱动，产出**一份 Output**
      交给各条路径。**不是轮询等它出现，是事实落链就叫一声**（见下"驱动"一节）。
```

"申请"走同一条：它也是"需要人拍板"，只是 `kind` 不同（今天只有 approval 这一种来源）。

## 出去：一份描述，多条路径

```python
@dataclass(frozen=True)
class Output:
    ref: str            # 身份：前端拿它读详情，飞书拿它做卡片 id
    kind: str           # approval | result | （以后的）request
    target_ref: str     # 指向哪件东西（task:<id>）
    title: str
    summary: str        # 给人看的摘要——**不是事实本身**
    actions: tuple[Action, ...]
    expires_at: str = ""
```

**内容由宿主描述、路径负责渲染。** 这条是照 occ-os 的通道门面抄的
（`app/domains/notification/channels.py`）：那时宿主给的是一张中性卡
（`type: timeline|metric|status|countdown`），飞书把它渲成 markdown 卡片，纯文本通道
回落成一行字。三条规矩值得原样保留：

1. **必选与可选分开**：`enabled()` / `send_text` 必选，`send_card` 等可选，缺的由门面兜底；
2. **单条路径失败隔离**：飞书挂了不拖累前端那一条，逐路径回执；
3. **调用者是宿主自己**，不是执行者（通道不是被审批的动作，它不走过 `function/` 那条管线）。

**内建的那条（前端）**：表现形式是**浮窗**——审批或申请到了就弹一个（`MarkdownOverlay`
的 `footer` 插槽本来就是给这个留的），而不是只在操作牌上亮一个徽标。用户在那儿点
批准/拒绝，产出的还是那条带着 `web:<principal>` 证据的命令。

**插件的那条**：扩展里要加**第五类条目 `channels`**（今天 manifest 只有
`tools / executors / schedules / providers`）。它的门面照 occ-os 那五格，第一个实现会是
飞书。**这一类不是"能力"**：它不走过 `function/` 那条判决管线——通道是宿主的手，
不是被审批的动作。

## 回来（callback）：**按钮带着意图，平台把点击推回来**

飞书的卡片按钮上带的是**这一刻的意图**（`task_id` + 动作 + 指纹 + 摘要）。点了之后
**平台把这次点击推回给我们**——走的是通道自己连出去的那根连接，落在宿主的
`answer()` 上（`app/build.py`），它再调 `callback.py::decide`——**判断只有这一份**。

**为什么不是 webhook**：这套系统是本地优先的，飞书的服务器**够不到** `127.0.0.1`。
为它开一个公网地址，等于把一个能起进程的控制面暴露出去，换一个按钮——不值。
长连接是**我们连出去**的，没有这个前提。（真要走 webhook，也只是"飞书怎么把点击
送到我们手上"换一种方式，`decide` 一个字不用改。）

**为什么不是签名链接**（这条路**已经删了**，理由记在 `callback.py` 的模块说明里）：
它要求**点的那台设备**够得到这台机器——手机在 4G 下就打不开；而且链接里能带的只有
"发给谁"，写不进"谁点的"，而回调体里**天然带着点击者的 `open_id`**。

**指纹是唯一的凭据**，它管两件事：

| 性质 | 靠什么 |
| --- | --- |
| **旧按钮自动作废** | `fingerprint` 对不上"现在等的那一件"就不认（工具请求一换，指纹就变）——这正是审批指纹今天的语义 |
| 只有那一个动作 | `value` 里只装得出 `approve` / `deny` 中的一个 |

**回来之后它就是一条普通命令**：`approve` / `deny`，只是证据那一格填
`channel:<open_id>`，而不是 `web:<principal>`。**几条路走的是同一条命令**——

| 从哪来 | 谁渲染 | 靠什么回来 | 证据（`external_ref`） |
| --- | --- | --- | --- |
| 前端（内建） | 操作牌 / 浮窗 | 接入面的认证（`access/`） | `web:<principal>` |
| 飞书卡片 | 插件 | **回调体**（长连接推回来） | `channel:<open_id>` |
| 以后的别的 | 各写各的 | 同上两种之一 | 各自说清"从哪儿来的" |

**复用就落在这一张表上**：同一份描述、同一条命令、不同的证据来源。所谓"支持多种输出路径"，
说的不是三套机制，是这一张表。

### 那根线**按需接上**，不是开机就接

宿主**不在启动时碰通道的回来路**（`Application.start()` 只起轮询）。递口子的时刻是
**第一次真的要把东西送出去之前**（`ChannelPath._arm` → `channels.arm`）。

这不是省事，是因为回来路**可能有前提**：飞书那条长连接占的是**独占资源**——那边是
**集群模式、不广播**，同一个应用的多条连接，每个事件只随机推给其中一个。所以它和
任何别的飞书客户端**共用应用就会互相吃事件**（落到我们这条上而没实现 handler 的，
会回 500，那一条对另一边就是永久丢失）。**没有东西要送的时候，就不该占着那根线。**

## 不新造"申请"

"申请"是**需要人拍板的事**，而今天内核里只有一种：工具调用要审批
（`FUNCTION_APPROVAL_REQUESTED` + `pending_fingerprint`）。它是这里的第三种 `kind`，
不是第五个原语。（真要异步申请——发了之后 Agent 接着干别的——那是动状态机的事，
和这一层无关。）

## 驱动：**事件驱动**（已定）

不轮询。**内核发生一件事，就送一件。**

但这里有一件必须先知道的事：**今天没有一个地方能听见"内核发生了一件事"。**

- 事实流（SSE）读的是 `gateway/audit.py` 的 `gateway_events` 表，而**只有 `facade.submit`
  往里写**——也就是说**只有命令面**；
- worker 自己发生的事（**请求审批**、跑完、失败）走的是
  `tasks/controller.py` → `gateway/function/pipeline.py` → `core/kernel.py`，
  **不经过门面、不进审计**；
- 前端也没有轮询兜底（只有 SSE 看门狗和两个时钟），所以「待拍板」今天是
  **下一次重读时**才出现在界面上的——**这是要先补的那件事，不是因为输出层才有的**。

事实的落点**只有一个**：`core/store.py::commit()`（"**唯一迁移通道**"，每一次状态变化
都要求同时给出一条事件，写不出"改了忘了记"的代码）。所以耳朵只可能插在那儿，
差别只在**谁递过去**：

| 候选 | 听得见什么 | 代价 |
| --- | --- | --- |
| **装配期把耳朵递进内核**（`Kernel(store, on_fact=…)`） | **全部**（命令面 + worker + 日程） | 内核多一行"如果有耳朵，说一声"——但依赖是**别人给的**，和 `_Registrar` / `last_tool_result` / `save_task_input` 同一条规矩 |
| 内核自己广播（模块级信号） | 全部 | 内核开始往外伸手。**不做。** |
| 挂在网关记账处（`facade.submit`） | 只有命令面 | **漏掉审批诞生的那一下**——而那正是最要送的东西 |

**倾向第一个**，顺带能把事实流也修成实时的（它今天只看得见命令面）。

**都定了**：

- 耳朵插在 `storage/control.py::transaction()` 的 `conn.commit()` **之后**（不是 `commit()`
  函数里面——那里还在事务里），由装配期递进来（`SqliteCoreStore(path, on_fact=…)`）；
- **"送过没有"不落盘**：`ChannelPath` 的内存里记最近 `SENT_MEMORY` 条。重启之后同一条
  还悬着的会再送一次——多一张卡片 vs 多一张表要维护，而"它还悬着"这句话再送一遍并不假。

## 落地顺序（四片）

| # | 落什么 | 为什么先做它 |
| --- | --- | --- |
| 1 | ✅ **那只耳朵**：`SqliteCoreStore(…, on_fact=…)`，事务提交成功后叫一声；`gateway/audit.py::fact()` 把听见的记进流水 | 后面三片都挂在它上面；顺带把事实流从"只看得见命令面"修成听得见全部事实 |
| 2 | ✅ `output.py` + `paths.py`：从事实派生 Output，交给各条路径 | 输出的形状 |
| 3 | ✅ 前端那一路：审批到了**弹浮窗**（`OutputOverlay`，复用 `MarkdownOverlay`） | 今天就能看见的收益 |
| 4 | ✅ `callback.py` + 扩展第五类条目 `channels` + 飞书包 | 凭据与外部路径 |

**第 1 片的已知代价**：一条命令现在会写**两行**流水（`facade` 记"谁提交了什么"，
耳朵记"内核确认了什么"）——事实流于是每条命令多发一帧，前端多读一次快照
（实测一次 ~13 ms / 62 KB）。换来的是一条**完整**的事实流。真嫌多的时候再合并，
但**别为了少一帧把它改成"只记命令面没记过的那些"**：那种判据会把"谁该记"变成一道推理题。

**它能听见的不只是审批**：实测一条日程跑完，流水里多了三行没人提交过的事实
（`TASK_CREATED` / `FUNCTION_CALLED` / `COMPLETED`）——改之前界面只知道"你按过触发"，
**它跑完了、成功了，界面永远不知道**。
