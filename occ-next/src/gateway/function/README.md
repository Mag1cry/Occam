# gateway/function/ — 对工具执行的权限鉴定

这个工具能不能跑。**判定在这里，不在内核。**

| 文件 | 装什么 |
| --- | --- |
| `pipeline.py` | 一次工具调用：判 → 定性 → 记账 → 执行 |
| `providers.py` | 找到供给，把调用递过去（两种供给在这里汇成一个形状） |
| `ports.py` | **句柄的契约**：`ToolSpec` / `ToolChannel` |

## 边界

- **内核只记账**。它收到的是"这次调用，判定是 X"，不是"请你判一下"。
- **判决只做一遍**。同一个调用不许出现第二个判定的地方。
- **prompt / 模型 / 消息不进这里**。这一层只认"工具 + 参数 + 判定"。
- **没有凭证参数**。判决在网关自己手里，签给自己就是自证，所以那条凭证删掉了。
  替代它的是**结构**：执行只有一个入口（`pipeline.py`），而它是四步一体的。

## 句柄从这里出去，不从供给方出去

**句柄如果由供给方递出来，谁拿到句柄谁就能调，判决就被绕过了。** 所以句柄从 gateway
出去——"调一次 = 判一次"是**结构上**成立的，不靠纪律。

两个实现，一个形状：

| 在哪 | 是什么 |
| --- | --- |
| **宿主里** | 真函数——包内工具是单例的方法，外部工具转发给 `mcp_client` |
| **worker 里** | 一个 stub，看着像函数，背后往 controller 发 `tool_request` |

跨进程传不了函数对象，所以过去的是 `ToolSpec` 的清单（名字 + schema）；但**两侧的
形状由这里定**，所以包作者和 agent 作者看到的永远是"一堆函数"。

（这和执行者的 `adapter` 正好相反：那个契约跟着**实现方**走，包作者照着写；
这个跟着**调用方**走，因为调用方要保证判决。）

## 四步，顺序固定，且只做一遍

```text
① 判      judge([工具被声明过, 这个执行者被允许用它], default="deny")
              ↓ 拒绝 → 回给 Worker，**不经过内核**
② 定性    显性声明的审批要求 → allow 或 needs_approval
③ 记账    告诉内核判定是什么 → 内核记一笔（控制事件 + 待审批状态）
              ↓ 仅 allow
④ 执行    providers
```

**①的条件全是"必须成立"，默认拒绝**——条件写在 `gateway/permission/judge.py` 的规则里。
"这个工具存在吗"就是"它被声明过吗"：**声明本身就是允许**。

## 审批必须显性指定，而且是**供给**那一格

一条 `tools` 声明 = 一个供给 = 一档审批。供给方不说它要不要批，就没有
"默认不用批"这回事——`approval_required` 是契约表里的**必填项**：

```yaml
tools:
  - name: workspace
    approval_required: true      # ← 必填；生成时默认就是 true
    url: http://127.0.0.1:8931/mcp        # 或者 entrypoint: provider.py:Weather
```

**为什么不写在单个工具上**：工具名要跑起来才知道（问服务器，或读单例有哪些函数），
没法提前写。想让两个工具审批不同，就分两个供给；要更细仍然有 `executors` 条目的
`tighten`（只能更严，ADR-027）。

**为什么不能由供给方自报**：那是自证。审批是**操作者的策略**，不是工具的属性；
`annotations` 里那些 hint 是服务器的说法，只能当提示。

**"能不能调"和"要不要人批"是两件事**，所以分两步走：先判能不能，再定性要不要问人。
塌成一个布尔值就分不出"不许"和"还没问"。

另外：**执行者只能收紧，不能放宽**（ADR-027）——声明说 `true` 就是 `true`，
执行者可以再收紧那些声明说 `false` 的，但反过来不行。

## 几种结果，一个都不能丢

| 判定 | 网关做什么 |
| --- | --- |
| `allow` | 执行，把结果回给 Worker |
| `needs_approval` | 原样把 `reason_ref` / `tool_id` 回给 Worker（它会进 interrupt） |
| 拒绝（工具不存在 / 执行者不许用） | 把理由回给 Worker，**不经过内核**——内核不知道有哪些工具 |
| 内核**抛错** | 回一条明确的拒绝，**不让监听线程静默退出** |

## 已知缺口

一次工具调用在内核侧留下的唯一痕迹是"**允许并开始了**"（ADR-008 有意不存返回值）。
但网关这边**连一条执行记录都没有**：工具调用不走 `facade.py`，`audit.py` 里看不见它，
结果如何只活在 Worker 的 checkpoint 里。

④ 之后应该补一条执行审计（tool_id、参数摘要、ok/err、耗时）——它和内核的
`FUNCTION_CALLED` 是两条不同的记录、两个不同的来源（ADR-037）。
