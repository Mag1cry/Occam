# gateway/permission/ — 判决的共同形状

两半权限鉴定共用的东西：**谁在请求、判成什么、按什么顺序判**。

| 文件 | 装什么 |
| --- | --- |
| `principal.py` | 主体：谁在请求（外部人 / 执行者 / 系统） |
| `decision.py` | 判决：允许 / 拒绝 / 需人批 |
| `judge.py` | 顺序器：只声明允许，默认拒绝 |

## 边界

- 只有**形状与顺序**，没有判据。判据在 `gateway/access/policy.py`（来源分级）和
  `gateway/function/pipeline.py`（声明、执行者范围、审批要求）。
- **不装记录**。留记录在 `gateway/audit.py` 和内核的事件链里——两半的记录落在不同的事实源
  （ADR-037）。
- **不装"谁在问"的分类**。`AccessLevel`（local / lan / external）是**判决的输入**，不是判决，
  它归 `access/policy.py`。

## 判决只有三种

| | 意思 |
| --- | --- |
| `allow` | 准许 |
| `deny` | 不许，并给出理由 |
| `needs_approval` | **准许，但要先问人** |

第三种必须和另外两种并列，不能塌成一个布尔值——`approved: false` 既可能表示"不许"，
也可能表示"还没问"。

## 规则只声明允许

```python
judge(requirements, *, default="deny") -> Decision
```

每一条是**必须成立的条件**：全成立才放行，任何一条不成立就用它的理由拒绝。
**默认拒绝**——"没被任何规则允许"就是拒绝，不需要有人显式禁止。

两半的默认值一样（都 fail-closed），条件不同：

| | 条件 |
| --- | --- |
| 访问 | 来源在信任网段 · 令牌对不对 |
| 调用 | 工具被声明过 · 这个执行者被允许用它 |

## 判决之后还有一步：定性

**"能不能调"和"要不要人批"是两件事**，分两步做：

```text
judge([...])  →  allow
                    ↓
显性声明的审批要求  →  allow 或 needs_approval
```

**审批必须显性指定**：一个工具不说它要不要批，就没有"默认不用批"这回事。
