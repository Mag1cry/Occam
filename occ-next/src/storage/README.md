# storage/ — 内核控制库

Task 表、控制事件。**内核的事实**存在这里。它是 `core/store.py` 那两个 Store
的唯一实现。

| 文件 | 装什么 |
| --- | --- |
| `schema.py` | 控制库 schema |
| `control.py` | SQLite 实现：事件链 checksum + prev_hash、损坏检测、尾部修复 |

## 边界

- **只有内核的事实**。派发记录、LangGraph checkpoint、审计流水、Worker 启动记录各有
  自己的库，在各自的目录里；扩展自己的数据在扩展包内。**开关没有库**——它是声明的一部分，
  而所有声明都在 `extensions/` 下（包清单，或日程文件）。
- **不导出存储给外围**。它只被 `app/build.py` 用来构造一次，绑进 `core/kernel.py`。
- 事件链是**链**：每条带前一条的 checksum。删掉或重排中间一条必须能被发现，而且
  **不许当作尾部损坏截掉**——那是"内部损坏"，只能人工处置。
- 发现内部损坏就停止追加：不在不可信的历史上制造新的控制事实。

## 它为什么独立成一个顶层目录

**因为内核不做 IO。** `core/` 的章程头一句就是"不运行、不做 IO、不判决"——所以
`core/store.py` 定义的是**事务和迁移通道的形状**，真正落盘的那一份必须住在外面。
这个目录就是它。

**这不是"库都住在这里"。** 别的库跟着它们的主人走：`tasks/launches.py`（对账的依据）、
`tasks/scheduler.py` 里的派发表、`gateway/audit.py` 的审计流水——那些地方**允许**做 IO。
只有内核那一份必须外置，因为它不许。

## 事件链的两种坏法，处置不同

| 坏法 | 判断依据 | 处置 |
| --- | --- | --- |
| **尾部撕了一角** | 只有最后一行失败，**而且失败原因是它自己内容坏了** | 可以截断（要有备份 + 显式确认） |
| **中间被动过** | 链断了（`prev_hash` 接不上），或中间某行内容坏了 | **不可截断**。链一断，后面每行都"证不了"，不是"已知坏" |

两条限定都不能少：光看位置，中间某条被改会让它和它之后的每一行都失败，会被误判成可截断的尾巴；
光看"哪一行失败"，删掉中间一条后剩下的最后一行恰好也会在链上失败——那一行完全可能就是最后一行。
